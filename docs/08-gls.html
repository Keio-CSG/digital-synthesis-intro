08 ゲートレベルシミュレーション

遅延情報 (SDF) を使い、実際の遅延でテストをもう一度流す。

はじめに: ゲートレベルシミュレーションとは

02章のシミュレーションは、遅延のない理想的な RTL で行いました。ゲートレベルシミュレーション (GLS) は、完成した回路（ネットリスト）に、実際の部品と配線の遅延を載せて、もう一度同じテストを流します。

遅延の情報は SDF というファイルに入っています。STA が「すべての経路が間に合うか」を見るのに対し、GLS は「テストした動作が、遅延込みで正しいか」を見ます。両方通れば、安心度が高まります。

実行方法

いちばん簡単make gls（リポジトリの最上位で実行）
直接実行cd sim; csh run_gls.csh setup 2.0 （使い方: csh run_gls.csh <setup|hold> <周期ns>）
入力icc2/MAC4.icc2.nopg.v、sta/MAC4.setup.sdf または MAC4.hold.sdf、tb/tb_MAC4.v、セルのシミュレーションモデル（config で指定）
出力sim/gls_setup_2.0.log、sim/gls_hold_2.0.log など
成功の確認grep -E "PASS|FAIL" sim/gls_setup_2.0.log → PASS: 400 cycles, no mismatch
  • 先に make sta で SDF を作ります。
  • 引数1は setup（遅いコーナーの遅延）または hold（速いコーナー）、引数2はクロック周期[ns]です。例: csh run_gls.csh hold 2.0。
  • 周期はテストベンチに +HALF（半周期）として渡されます。

STA は「すべての経路を見る」代わりに論理を見ません。ゲートレベルシミュレーション (GLS) は「テストした動作が、遅延込みで正しいか」を見ます。両方そろって安心できます。

ここでも Cadence Xcelium を使います（xrun）。

  • ネットリスト: 配置配線後のもの。
  • セルのシミュレーションモデル: セルライブラリが提供する Verilog。
  • SDF: 各セル・配線の遅延表（PrimeTime が出力）。-sdf_cmd_file で DUT のスコープに当てる。
  • テストベンチ: RTL と同じもの。クロック周期だけ +HALF で変える。

よく出る症状

症状原因
出力が x のままリセット解除がクロックエッジに近すぎる（recovery/removal 違反）。または SDF のスコープ違い。
周期を縮めると不一致setup 違反（本物）。STA の結果と照らし合わせる。
SDF 適用ログに大量の警告階層名の不一致。sdf_*.log を確認。
どのSDFで流す？
遅いコーナーの SDF で setup、速いコーナーの SDF で hold を見ます。両方 PASS が望ましい。

演習

  1. make gls の周期を 2.0 → 1.0 に縮めて PASS/FAIL を観察する。
  2. 02章の演習（リセットを #23 で解除）で、x が出る様子を確認する。
