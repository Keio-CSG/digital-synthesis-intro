02 RTLとシミュレーション

題材 MAC4 と、自己チェック付きテストベンチ。

はじめに: RTL とは、シミュレーションとは

RTL（Register Transfer Level）は、回路を「レジスタ（値を覚える部品）」と「レジスタ間で行う計算」で書く抽象度のことです。「クロックが1回来るたびに、この値とこの値を足して、このレジスタに入れる」といった動作を、Verilog という言語で書きます。

ソフトウェアのプログラムは上から順に実行されますが、ハードウェアの記述は「全部の部品が同時に動いている」様子を書いたものです。ここが最初に戸惑うところです。

クロックは一定の間隔で打たれる合図で、レジスタはクロックの立ち上がりの瞬間にだけ新しい値を取り込みます。デジタル回路はこの合図に合わせて、一歩ずつ進みます。

シミュレーションは、作った回路の動きをコンピュータ上で再現して確かめることです。テストベンチは、回路に入力を与えて出力を確認する「テスト用の回路」で、実際のチップには入りません。

実行方法

いちばん簡単make sim（リポジトリの最上位で実行）
直接実行cd sim; csh run_rtl.csh
入力rtl/MAC4_LANE.v, rtl/MAC4.v, tb/tb_MAC4.v
出力sim/rtl.log（実行ログ）、sim/wave.vcd（波形データ）
成功の確認grep PASS sim/rtl.log → PASS: 400 cycles, no mismatch
  • 波形を見たいときは wave.vcd を波形ビューアで開きます（信号が時間とともにどう変わるか見られます）。
  • RTL を直したら、そのまま make sim をもう一度実行するだけです（毎回コンパイルからやり直します）。
  • スクリプトの中身: xrun（シミュレータ）に、RTL とテストベンチを渡しています。-access +r は信号を読める状態にする指定、-define DUMP は波形を出力する指定です。

題材: 4レーン乗加算器 (MAC4)

1レーンは 4bit × 4bit の乗算結果を 12bit のアキュムレータに足し込む回路で、入力にレジスタが付いています。これを4レーン並べ、クロックとリセットを共有します（約90個のフリップフロップ）。小さいですが、クロックツリーが必要になるくらいの数です。

図の左が4レーンを並べたトップ、右が1レーンの中身です。データは 入力レジスタ → 乗算 → 加算 → アキュムレータと流れ、アキュムレータの値は次のサイクルの加算にフィードバックされます。

シミュレータは Cadence Xcelium（xrun）です。

テストベンチ

乱数入力を DUT と振る舞いモデルに同時に与え、毎サイクル出力を比べます。人が波形を見なくても PASS/FAIL が出ることが重要です。後のゲートレベルシミュレーションでも同じテストベンチを使います。

つまずきポイント: リセットの解除タイミング
リセットをクロックエッジちょうどで解除すると、ゲートレベルでは recovery 違反になり出力が X になります（RTLでは気づけません）。テストベンチでは @(negedge clk) で解除しています。

演習

  1. MAC4_LANE.v のアキュムレートを acc + a_q*b_q から acc + a_q+b_q に変えて、テストが FAIL になることを確認する。
  2. リセット解除を #23 rst_n = 1; に戻すとどうなるか、08章の後で試す。
