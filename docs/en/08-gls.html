08 Gate-Level Simulation

Use the delay information (SDF) and run the test again with real delays.

Background: what is gate-level simulation?

The simulation in chapter 02 used ideal RTL without delays. Gate-level simulation (GLS) takes the finished circuit (the netlist), adds the real delays of parts and wires, and runs the same test again.

The delay information is in a file called SDF. STA asks "does every path make it in time?", while GLS asks "is the behaviour we tested correct with the delays?". If both pass, confidence is high.

How to run

Easiestmake gls (from the top of the repository)
Directlycd sim; csh run_gls.csh setup 2.0 (usage: csh run_gls.csh <setup|hold> <period in ns>)
Inputsicc2/MAC4.icc2.nopg.v, sta/MAC4.setup.sdf or MAC4.hold.sdf, tb/tb_MAC4.v, the cell simulation models (set in config)
Outputssim/gls_setup_2.0.log, sim/gls_hold_2.0.log and so on
Check successgrep -E "PASS|FAIL" sim/gls_setup_2.0.log → PASS: 400 cycles, no mismatch
  • Run make sta first to produce the SDF.
  • Argument 1 is setup (delays of the slow corner) or hold (fast corner); argument 2 is the clock period in ns. Example: csh run_gls.csh hold 2.0.
  • The period is passed to the testbench as +HALF (half period).

STA looks at all paths but does not look at the logic. Gate-level simulation (GLS) checks that the behaviour you tested is correct with the delays included. You feel safe only when both agree.

The simulator is Cadence Xcelium again (xrun).

  • Netlist: the one after place and route.
  • Simulation models of the cells: Verilog provided with the cell library.
  • SDF: the delay table of every cell and wire (written by PrimeTime). It is applied to the DUT scope with -sdf_cmd_file.
  • Testbench: the same as for RTL. Only the clock period is changed with +HALF.

Common symptoms

SymptomCause
Outputs stay xReset released too close to the clock edge (recovery/removal violation), or the wrong SDF scope.
Mismatch when the period is shortenedA setup violation (real). Compare with the STA result.
Many warnings when the SDF is appliedHierarchy names do not match. Check sdf_*.log.
Which SDF to use?
Check setup with the SDF of the slow corner and hold with the SDF of the fast corner. Both should PASS.
