07 Signoff STA

With the real wire parasitics, check setup and hold, each at its worst corner.

Background: what are signoff STA, setup and hold?

STA (static timing analysis) calculates, for every path in the circuit, "does it make it in time?" without running a simulation. You do not have to think up inputs, and nothing is missed.

Data going from one register to another has to arrive within one clock cycle. There are two conditions to check.

  • setup: has the data arrived before the next clock? Too late is bad.
  • hold: after the clock, does the data change too early? Too early is bad.

slack is the margin: 0 or more passes, negative is a violation. Signoff STA is the final judgement including the wire resistance and capacitance (SPEF).

How to run

Easiestmake sta (from the top of the repository)
Directlycd sta; env MODE=setup pt_shell -f pt.tcl and env MODE=hold pt_shell -f pt.tcl
Inputsicc2/MAC4.icc2.nopg.v, rcx/MAC4.spef, const/MAC4.sdc, the cell timing library (set in config)
Outputssta/setup.*.log, sta/hold.*.log, MAC4.setup.sdf, MAC4.hold.sdf (delay files used in the next chapter's simulation)
Check successgrep "slack (" sta/setup.max.log | head -1 / grep "slack (" sta/hold.min.log | head -1 → both slack (MET)
  • make pnr rcx must have been run.
  • It runs twice because setup and hold are checked separately, at different corners.

The tool is Synopsys PrimeTime (pt_shell). This is the final judgement. The timing in synthesis and ICC2 is only progress; whether you can tape out is decided by signoff static timing analysis.

Why run it twice?

CheckWorst whenCorner used
setup (is the data too late?)data slow, clock earlyslow corner (low voltage, high temperature)
hold (is the data too early?)data early, clock latefast corner (high voltage, low temperature)

Even for the same circuit, delays change a lot with the operating condition. Run MODE=setup and MODE=hold separately.

Key points of the script

  • read_verilog + link_design: the netlist written by ICC2.
  • source const/MAC4.sdc: the same SDC as synthesis. The constraints must not change along the way.
  • read_parasitics: read the SPEF.
  • set_propagated_clock: propagate the clock through its real paths.
  • check_timing: gaps in the constraints (inputs without delay, registers the clock does not reach). Even with good slack, you cannot trust the result if there are warnings here.

Reading the result

  • *.max.log / *.min.log: details of the worst paths (-input_pins shows the delay of every cell).
  • *.violators.log: list of violations. It should be empty.
  • *.skew.log: clock skew.
  • *.annotated.log: the share of nets that got parasitics.
  • *.coverage.log: how completely the paths were analysed.
A small hold slack is normal
Hold does not depend on the period; slowing the clock does not help. The only fix is inserting delay cells. That is why ICC2 fixes it at the CTS stage.

What to do on a violation

ViolationRemedy
setupLengthen the period / make the logic shallower (pipelining) / use cells with stronger drive / place things closer
holdInsert delay cells / adjust the clock skew

Exercises

  1. Set CLK_PERIOD to 1.0 and run from scratch (make clean all). At which step does a negative slack first appear?
  2. Delete the set_propagated_clock line and compare the results. What changes, and why?
