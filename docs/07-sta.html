07 signoff STA

実配線の寄生込みで、setup と hold をそれぞれ最悪のコーナーで確認する。

はじめに: signoff STA とは、setup と hold とは

STA（静的タイミング解析）は、シミュレーションを行わずに、回路内のすべての経路について「間に合うか」を計算する手法です。入力を考える必要がなく、漏れがありません。

レジスタからレジスタへのデータは、クロックの1周期のあいだに届かなければなりません。確認する条件は2つあります。

  • setup（セットアップ）: 次のクロックが来る前に、データが届いているか。遅すぎるとだめ。
  • hold（ホールド）: クロックが来た後、データが変わるのが早すぎないか。早すぎるとだめ。

slack（スラック）は「余裕」のことで、0以上なら合格、マイナスなら違反です。signoff STA は、配線の抵抗・容量（SPEF）まで含めた最終判定です。

実行方法

いちばん簡単make sta（リポジトリの最上位で実行）
直接実行cd sta; env MODE=setup pt_shell -f pt.tcl と env MODE=hold pt_shell -f pt.tcl
入力icc2/MAC4.icc2.nopg.v、rcx/MAC4.spef、const/MAC4.sdc、セルのタイミングライブラリ（config で指定）
出力sta/setup.*.log、sta/hold.*.log、MAC4.setup.sdf、MAC4.hold.sdf（次章のシミュレーションで使う遅延ファイル）
成功の確認grep "slack (" sta/setup.max.log | head -1 ／ grep "slack (" sta/hold.min.log | head -1 → どちらも slack (MET)
  • make pnr rcx が済んでいる必要があります。
  • setup と hold を別々に（別のコーナーで）実行するため、2回走ります。

ツールは Synopsys PrimeTime（pt_shell）です。ここが最終判定です。合成・ICC2 のタイミングは途中経過で、テープアウト可否は signoff の STA（静的タイミング解析）で決まります。

なぜ2回走らせるのか

チェック最悪になる条件使うコーナー
setup（データが遅すぎないか）データは遅く、クロックは早く遅いコーナー（低電圧・高温）
hold（データが早すぎないか）データは早く、クロックは遅く速いコーナー（高電圧・低温）

同じ回路でも、動作条件が変わると遅延が大きく変わります。MODE=setup と MODE=hold で別々に実行します。

スクリプトの要点

  • read_verilog + link_design: ICC2 が出したネットリスト。
  • source const/MAC4.sdc: 合成と同じ SDC。制約が途中で変わっていないこと。
  • read_parasitics: SPEF を読む。
  • set_propagated_clock: クロックを実際の経路で伝搬させる。
  • check_timing: 制約の抜け（入力に遅延が無い・クロックが来ないレジスタなど）。slack が良くても、ここに警告があれば信用できません。

結果の読み方

  • *.max.log / *.min.log: 最悪パスの詳細（-input_pins でセルごとの遅延が見える）。
  • *.violators.log: 違反の一覧。空であること。
  • *.skew.log: クロックスキュー。
  • *.annotated.log: 寄生が付いたネットの割合。
  • *.coverage.log: 解析されたパスの網羅度。
hold の slack が小さいのは普通
hold は周期に依存せず、クロックを遅くしても改善しません。修正は遅延セルの挿入しかありません。ICC2 の CTS 段階で直す理由です。

違反したときの打ち手

違反対策
setup周期を延ばす / 論理を浅くする（パイプライン）/ ドライブの強いセルへ / 配置を近づける
hold遅延セル挿入 / クロックスキューを調整

演習

  1. CLK_PERIOD を 1.0 にして最初から流す（make clean all）。どの段で最初に負の slack が出るか。
  2. set_propagated_clock の行を消して結果を比べる。何が変わるか、なぜか。
