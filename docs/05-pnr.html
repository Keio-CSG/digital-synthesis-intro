05 配置配線

フロアプランからクロックツリー合成、配線、GDS出力まで。

はじめに: 配置配線とは、クロックツリーとは

ネットリストは「どの部品がどの部品につながるか」という接続表で、位置の情報がありません。配置配線（P&R: Place and Route）は、これをチップの上に実際に並べ、金属の配線でつなぎます。

  • フロアプラン: チップ（ブロック）の大きさと、入出力端子の位置を決める。
  • 電源配線: すべての部品に電気を送る太い配線を張る。
  • 配置: 部品を並べる。つながりの多いものを近くに置くと配線が短くなります。
  • クロックツリー合成 (CTS): クロックを全レジスタにほぼ同時に届けるための、バッファの木を作る。
  • 配線: 部品同士を金属でつなぐ。

配線は長いほど遅くなるため、ここで初めて「実際の遅さ」が見えてきます。最終的に、工場に渡す図面データ GDS が出力されます。

実行方法

いちばん簡単make pnr（リポジトリの最上位で実行）
直接実行cd icc2; icc2_shell -f icc2.tcl >& icc2_run.log
入力dc/MAC4.net.v（ネットリスト）、const/MAC4.sdc、テクノロジ・セルのデータ（config で指定）
出力icc2/MAC4.gds（レイアウト）、MAC4.icc2.nopg.v・MAC4.icc2.lvs.v（ネットリスト）、MAC4.icc2.sdf、MAC4.def、レポート
成功の確認grep -E "^Error" icc2/icc2_run.log → 何も出なければ OK ／ grep "slack (" icc2/MAC4.cts.timing.log | head -1
  • 先に make syn。実行時間は1分半〜2分ほどです。
  • コアの大きさを変えるには、icc2/icc2.tcl の core_width / core_height を編集します。
  • 実行のたびに icc2/MAC4.ndm を作り直します（古いものは自動で消えます）。

ツールは Synopsys IC Compiler II（icc2_shell）です。ネットリストを実際の形にします。配置配線で初めて「配線遅延」「クロックツリー」「電源網」が現れます。

手順の全体像

  1. ライブラリ作成・ネットリスト読み込み（create_lib, read_verilog, link_block）
  2. RC モデルとシナリオ: 寄生モデルと、SDC を読み込んだシナリオ（setup と hold を両方解析）
  3. フロアプラン: コアの大きさと、ピン配置（initialize_floorplan, place_pins）
  4. 電源網: 縦の電源ストラップと、セル列の電源レール、その間をつなぐビア（create_pg_*, compile_pg）
  5. 配置: place_opt — セルを置き、タイミングを見ながら最適化
  6. クロックツリー合成 + hold 修正: clock_opt
  7. 配線: route_auto, route_opt、check_routes
  8. フィラーで隙間を埋める
  9. 出力: ネットリスト（検証用）、GDS、DEF、SDF

フロアプラン

面積の目安: セル面積の合計 ÷ 目標利用率（ここでは約 50%）≒ コア面積。狭すぎると配線できず、広すぎると配線が長くなります。

クロックツリー合成 (CTS)

配置の時点ではクロックは理想（全フリップフロップに同時に届く）として扱われます。clock_opt でクロックバッファの木を作り、各フリップフロップへの到着時間のばらつき（スキュー）を揃えます。同時に、データが早く着きすぎる hold 違反を遅延セルの挿入で直します。

小さな回路では CTS が何もしない
フリップフロップが20個ほどなら、クロックポートが全部を直接駆動でき、バッファが入りません。このコースで4レーンにしているのは、ツリーができる様子を見るためです。

できあがったものを見る

ツールのビューアがなくても結果を確認できるよう、GDS と DEF から画像を作るスクリプト（tools/render_layout.py、python3 tools/render_layout.py）を付けています。

レポートの見どころ

ファイル見るもの
MAC4.pre_cts.timing.logCTS 前の setup（クロック理想）
MAC4.cts.timing.logCTS 後の setup（クロック伝搬）。配線遅延が入って slack が減る
MAC4.cts.hold.logCTS 後の hold。修正前は負になりやすい
MAC4.cts.skew.logスキュー・レイテンシ・バッファ数
MAC4.check_routes.log配線の DRC/オープン/ショート（0 であること）
電源は「引いた」だけでは足りない
電源レールが上位の電源とビアでつながっていないと、タイミングも DRC も通るのに、LVS だけが落ちます。電源網を作った直後に、ビアが全部のレールに付いたかを確認してください（この教材では実際にそれで一度つまずきました）。
ICC2 の結果は暫定
ICC2 内の寄生抽出は簡易です。最終判断は次章以降の StarRC + PrimeTime で行います。

演習

  1. core_width を 90 に広げて再実行。配線長（cts.skew.log の Wire Length）はどうなるか。
  2. CTS 前後の setup slack を比べ、なぜ変わるか説明する。
