03 論理合成

SDC でゴールを決め、DC でゲートに変換する。

はじめに: 論理合成とは、制約とは

RTL は「何をするか」を書いたもので、そのままでは実際の部品に対応していません。論理合成は、これを AND・OR・フリップフロップ（1ビットの記憶）といった基本部品（スタンダードセル）の接続表に変換する作業です。変換結果をネットリストと呼びます。

同じ RTL からでも、部品の選び方で回路は変わります。速くすれば面積が増え、小さくすれば遅くなります（トレードオフ）。そこで「どれくらいの速さを目指すか」を制約（SDC）として人が与え、ツールがそれを満たす最小の回路を探します。

スタンダードセルのライブラリは、部品の形・面積・遅延の一覧表です。合成ツールは、その遅延の値を使って「間に合うか」を計算します。

実行方法

いちばん簡単make syn（リポジトリの最上位で実行）
直接実行cd dc; dc_shell -f dc.tcl >& dc_run.log
入力rtl/*.v, const/MAC4.sdc, セルのタイミングライブラリ（config で指定）
出力dc/MAC4.net.v（ネットリスト）、MAC4.ddc、MAC4.sdc、MAC4.sdf、各種レポート MAC4.*.log
成功の確認grep slack dc/MAC4.max.timing.log | head -1 → slack (MET)
  • 周期を変えて試すときは、const/MAC4.sdc の CLK_PERIOD を書き換えて、もう一度 make syn。
  • コーナーを変えるときは、環境変数 CORNER に wc / tc / bc を指定して直接実行します（例: cd dc; env CORNER=tc dc_shell -f dc.tcl）。
  • 途中で止まったら dc/dc_run.log の Error を探します。

論理合成は「RTL を、制約を満たすゲートの接続に変換する」作業です。ここでは Synopsys Design Compiler（dc_shell）を使います。制約（SDC）こそが仕様書で、同じ RTL でも制約が違えば別の回路になります。

1. 制約 (SDC)

コマンド意味
create_clockクロック周期 = 2.0 ns（500 MHz）。ここが目標性能。
set_clock_uncertaintyスキュー・ジッタの余裕。setup は大きく、hold は小さめに。
set_input_delay / set_output_delay前後のブロックが使う時間。入出力パスの持ち時間は 周期 − delay になる。
set_input_transition / set_load入力の波形のなまりと、出力の負荷。
set_false_path -from rst_n非同期リセットはクロックとの関係を見ない。

2. 合成スクリプトの流れ

  • analyze → elaborate → link: RTL を読み、階層をつなぎ、セルライブラリに結び付ける。
  • check_design: 未接続・多重ドライバがないか。警告は必ず読む。
  • compile_ultra: 論理の最適化とセルへのマッピング。
どのコーナーで合成する？
setup（遅すぎないか）は遅いコーナー、hold は速いコーナーで見るのが原則です。このスクリプトは CORNER=wc|tc|bc で切り替えます（既定: wc）。数値を書くときは必ずコーナーを併記してください。

3. レポートの読み方

  • MAC4.max.timing.log: 最も厳しい setup パス
  • MAC4.min.timing.log: hold パス
  • MAC4.area.log: 面積。
  • MAC4.qor.log: 全体の要約。
この段階のタイミングは理想値
配線の遅延もクロックツリーもありません。合成で slack に余裕があっても、配置配線後に減ります。07章の signoff が最終判断です。

演習

  1. CLK_PERIOD を 1.5 にして make syn。slack は負になるか？ 面積はどう変わるか？
  2. 同じ周期で CORNER=tc と CORNER=wc を比べる。
  3. set_false_path を消すと何が変わるか（report_timing の端点を見る）。
