09 物理検証 (DRC / LVS)

製造ルールを守っているか、回路図と一致しているか。

はじめに: DRC と LVS とは

工場は、チップを作るときの守るべき寸法のルール（配線の最小幅・最小間隔など）を決めています。DRC（Design Rule Check）は、完成したレイアウトがそのルールに違反していないかを、図形のレベルで検査します。

LVS（Layout Versus Schematic）は、レイアウトの図形からトランジスタとつながりを取り出し、回路図（ネットリスト）と同じ回路かを照合します。配線の誤接続などを発見できます。

タイミングが合っていても、製造ルール違反や接続ミスがあれば、チップは作れません。そのため、物理検証も signoff の一部です。

実行方法

いちばん簡単make drc と make lvs（リポジトリの最上位で実行）
直接実行cd verif; csh run_drc.csh と csh run_lvs.csh
入力icc2/MAC4.gds、icc2/MAC4.icc2.lvs.v（LVSのみ）、ルールデック（config で指定）
出力verif/drc/MAC4.drc.summary、verif/drc/drc.nonzero.txt（違反のあるルール一覧）、verif/lvs/MAC4.lvs.report
成功の確認cat verif/drc/drc.nonzero.txt ／ grep -E "CORRECT|INCORRECT" verif/lvs/MAC4.lvs.report
  • どちらも先に make pnr。DRC は1分ほどです。
  • DRC の結果は、ルール名ごとの違反数を読みます。0 でないものを分類してください。

ツールは Siemens Calibre です。タイミングが通っても、製造できる形か、ネットリストどおりの回路かは別問題です。

DRC (Design Rule Check)

配線の幅・間隔・密度などの製造ルールを、GDS に対して検査します。

見え方意味
ルールごとの違反数*.drc.summary の RULECHECK ... Result Count。0 でないものを読む。
チップ全体向けのルール（シールリング・境界）単体ブロックでは必ず出る。フルチップで解消するため、ブロック段階では除外してよい。
ダミーパターン／密度ルールフィルを入れるフェーズで解消する。ブロック単体では残ることが多い。

この教材では、実際の配線の幾何ルール違反は無しで、残るのは密度・ダミー・チップ全体向けのルールです（一覧は verif/drc/drc.nonzero.txt）。

LVS (Layout Versus Schematic)

レイアウトからトランジスタと接続を取り出し、ネットリスト（回路図側）と照合します。

  1. ネットリストをトランジスタ単位の SPICE に変換（セルの中身はライブラリの SPICE から）。
  2. レイアウトを抽出し、デバイス数・ネット数・接続を照合。
  3. レポートの先頭の CORRECT / INCORRECT、続いて INITIAL NUMBERS OF OBJECTS（レイアウトとソースの個数の比較）を見る。

レポートの読み方

見るところ意味
OVERALL COMPARISON RESULTSCORRECT が合格
INITIAL NUMBERS OF OBJECTSMOS トランジスタ数が一致しているか（デバイスは合っているのに接続が違う、など切り分けに使う）
INCORRECT NETS / INCORRECT INSTANCESどのネット・素子で食い違うか

実例: LVS が落ちた原因は電源だった

このコースを作る途中で、LVS が INCORRECT になりました。調べ方は次のとおりです。

  1. INITIAL NUMBERS OF OBJECTS を見ると、トランジスタ数は一致。部品は合っているので、接続の問題。
  2. 標準セル1個だけで LVS を実行すると CORRECT。セルの中は正しい。
  3. INCORRECT INSTANCES の中身を読むと、トランジスタの基板側（b:）が、回路図では VDD/VSS なのに、レイアウトでは名前のない別のネットになっている。
  4. 電源の配線データを調べると、標準セルの電源レールが、上位の電源ストラップにビアでつながっていないものがあった（ビアが設計ルールに引っかかって消えていた）。
  5. ストラップを縦方向だけにし、ビアの形を選び直して再実行 → LVS CORRECT、DRC もルール違反なし。
学べること
電源が切れていても、タイミング解析（理想的な電源を仮定）と DRC は通ってしまいます。LVS だけが、配線のつながりを本当に確認する検査です。
ブロック単体とフルチップの違い
電源ピン・シールリング・IOなどがない単体ブロックでは、DRC/LVS 共に特有の違反・不一致が出ます。何がブロック単体の都合で、何が実際の問題かを区別するのが物理検証の腕の見せ所です。

演習

  1. drc.nonzero.txt に並ぶルールを、「配線の幾何」「密度・ダミー」「チップ全体」の3つに分類する。
  2. icc2/icc2.tcl のビア指定を一時的にこわして（例: ストラップの層を変える）再実行し、LVS がどう落ちるか、レポートの INCORRECT NETS を読む。
